# Shared CAD support: isolated experiment

The current editor deliberately refuses an ambiguous or shared serialized surface. `tests/sharedSupportFixture.test.ts` constructs an OCCT box, splits its top with an edge, sews a valid seven-face solid, exports and imports STEP, and reproduces the refusal on a top face. The original imported BREP remains unchanged.

The same test exports that face alone, edits an interior control pole by 0.02 mm through a separate `SurfaceEditorKernel` in G1 mode, and sews the resulting face together with the six original faces. On this synthetic planar case, the result and STEP round-trip are valid, contain one solid and seven faces, and have a detectable interior change. One central sample from each other face remains within 1e-6 mm of the resulting skin. This is a feasibility experiment, not a production editing path or QuickSurface comparison.

The current shared-support guard remains in place. Before integrating this method, independently check complete boundary and neighboring-face geometry, pcurves, orientation, self-intersection and tolerances, resource cleanup, failure atomicity, face identity, Undo/Redo, notes and a versioned save/replay contract. Sampling six face centers does not establish preservation of whole faces or global G1 continuity. General curved or rational faces, repeated STEP and application interaction remain unqualified.

`ExperimentalSharedPlane` packages the isolated experiment as a separate research adapter, without connecting it to the worker or UI. It restricts input to a single valid solid and a four-edge planar face, protects the isolated face with existing G1 checks, rejects sampled intersections away from the original boundary, and checks output topology. Sewing and sections run on a copy made from the retained BREP: a comparison detected that sewing could otherwise alter the retained source. The adapter compares each serialized face before using its index and invalidates its instance if the retained source changes, including on failure. On the same synthetic box an interior edit survives round-trip; a protected-pole edit and a deformation intersecting the opposite wall are refused before a later valid edit succeeds. Identity across arbitrary imports, full neighboring geometry, pcurves, fault-injection coverage and production integration remain unqualified.

A simulated alteration of serialized source data causes the adapter to reject the output and close the instance; this covers that failure path only. Comparing serialized faces is deliberately conservative and may refuse equivalent faces whose serialization changes. The test uses fault injection for this check, not actual source corruption.

The adapter now matches each other face one-to-one using type, orientation, area, and bidirectional sampled distances at UV-grid and topological-edge points. In the box test it rejects a translated neighbor, an inverted neighbor and an injected non-finite distance; an unchanged result passes. These checks can conservatively refuse valid cases, are computationally expensive, and do not establish exact preservation between samples or verify all pcurves and topology. The production guard remains unchanged.

Two explicit experimental worker actions prepare and evaluate a shared planar face using a fresh isolated adapter and the STEP supplied with each request. They do not share the active selection or publish a preview. A simulated-transport test with the real dispatcher and OCCT verifies a valid recomposition, rejection of an invalid pole edit, and preservation of the active editor's preview witness. This repeats STEP import per request and is not yet an interactive or persistence contract. No browser worker, actual restart, notes, Undo/Redo or host integration has been qualified.

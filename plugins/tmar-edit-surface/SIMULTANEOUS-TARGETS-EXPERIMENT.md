# Simultaneous finite surface-point targets

`surfacePointTargetsExperimental.ts` accepts two to eight UV/target constraints on a fixed rational NURBS net. It reuses `targetSurfacePoint` unchanged as a minimum-norm projection onto one point constraint. Up to 64 cyclic passes are allowed; a result is returned only after every residual, measured on the same final net, satisfies the requested tolerance. The cumulative displacement of every pole relative to the input net is checked after each projection. Duplicate UVs, insufficient influence, exceeded budgets and failure to converge refuse without changing the source. Conservatively refusing a slow but solvable system is allowed.

The caller must retain all contacts that need preservation. This helper does not store contacts, pick a scan, classify trims, authorize poles, verify reference/source lifetime or publish CAD. There is no new user control or host integration; the existing single-target path remains unchanged. An eventual caller must apply the existing lock, trim, boundary and revision checks, resolve every CAD anchor, then commit the accepted candidate once and await normal CAD validation. No surface-to-scan fit, region deviation bound or QuickSurface equivalence is established by satisfying a finite set of constraints.

Two mathematical tests passed with rational bicubic coefficients, demonstrating that sequential targeting can disturb the first contact while the simultaneous solve preserves both. They also check unauthorized poles, source/basis preservation and explicit refusal cases. A separate real SurfaceDraft/dispatcher/OCCT test used an imported synthetic STEP solid with a top face refined exactly to 7x7. After one contact was established, adding the second while retaining the first converged in three passes. Independent STEP evaluation measured maximum point residual 3.9145e-13 mm. At 68 boundary samples maximum displacement was 1.9896e-13 mm and minimum source/result normal dot was 1. One geometry Undo restored the first-contact net and a valid solid; one manually locked pole remained exact. The source BREP was unchanged. Worker transport is simulated in process; no browser, scan or host project was used. Receipt: `evidence/simultaneous-surface-targets/result.json`.

## Experimental controller and CAD-anchor integration

`SurfaceDraft.targetPointsExperimental` now obtains permissions from the exact validated snapshot, excluding manual, trim, hidden and G0/G1-protected poles. It verifies every anchor with the real existing `noteResolve` action at that preview revision and compares the native position with the solver's original point. A changed snapshot, reference lifetime, unsupported preparation, trim rejection or mismatched point refuses before any geometry/history commit. The candidate is committed once and remains unverified until normal CAD evaluation succeeds; a CAD refusal remains invalid and a single Undo restores the preceding geometry.

`WorkspaceSurfaceSession.targetSurfacePointsExperimental` is a controlled experimental entry for two to eight part-coordinate seeds. It asks CAD for every UV/normal through `notePick`, obtains each external scan/CAD target through the existing resolver contract, retains every reference's currentness callback and fences source/face/operation changes through the last anchor verification. The ordinary single-target API and UI remain unchanged. No batch UI is mounted: there is no qualified interaction yet for collecting and reviewing several contacts, so no simulated input controls are presented to users.

Fourteen targeted draft/controller guard checks and the real CAD draft integration passed. The latter now uses actual `notePick` and `noteResolve` actions for both contacts rather than committing the mathematical result directly; independent STEP residual and Undo measurements remain those recorded above. Controller reference tests use controlled callbacks, while the native test's targets are immutable synthetic coordinates. A highly correlated G0 permission fixture conservatively hit the documented 64-pass limit; permission verification uses a well-conditioned pair without changing that limit. This is not a real scan batch, application GUI or project qualification. Receipt: `evidence/simultaneous-surface-targets/controller-integration.json`.

## Collection and review flow checkpoint

The workspace panel now offers an explicit multi-point option beside the existing scan/external-CAD target commands. The same CAD face click and real THREE reference resolver collect up to eight pairs against one unchanged draft snapshot. Each pair retains its CAD anchor, chosen reference and currentness callback. The panel lists reference label, source/destination part coordinates and gap; blue/orange viewport markers show each pair. A point can be removed before applying. Collection creates no geometry/history entry. Apply requires at least two pairs, re-verifies all anchors/references and creates one geometry commit; Cancel or Escape discards collection. A host reference-change notification cancels the collection conservatively. Single-target mode remains available.

The live-region text changes with additions/removals and announces when Apply is available. Native controls preserve keyboard semantics; after removal the next/previous Remove button (or Cancel) receives focus. Exiting collection returns panel/body focus to its start control, or to the collection toggle while CAD validation disables that start control. The existing UI harness uses server-rendered markup: count/availability assertions pass, but browser focus, keyboard and screen-reader behavior have not been executed.

Eight focused controller/layer checks, one panel-markup check and one real session/dispatcher/OCCT collection test passed. The native test used actual THREE ray intersections on two synthetic external patches, reviewed both pairs without changing geometry, applied one batch, reimported a valid six-face/one-solid STEP and restored the original net with one Undo. Maximum independent target-to-skin distance was 7.1553e-8 mm. Its worker transport is simulated and reference lifetime fixed; the layer's actual picker/resolver is checked separately with a simulated viewport lease. No browser, host or user project was changed. Receipt: `evidence/simultaneous-surface-targets/collection-ui-checkpoint.json`. Earlier notes stating there is no batch UI describe the preceding checkpoint; this source flow still requires independent GUI acceptance before product qualification.

### Precommit refusal preserves the review list

A later isolated GUI run collected three clicks and verified remove/focus, but the retained two targets at a 0.25 mm scan offset refused with `Spostamento dei poli oltre il limite autorizzato.` The source CAD stayed valid and unchanged. The report does not retain the exact UVs and authorized basis coefficients, so the precise required pole budget is not measured; a point offset is not a pole displacement, especially near protected boundaries. No limit was increased.

`applySurfaceTargets` previously cleared the collection unconditionally on any error. The draft now identifies refusals occurring during mathematical candidate computation, before anchor verification or geometry commit. For that refusal only, the controller keeps the pairs if the exact snapshot and source/operation/reference lifetime still pass. The user can review, remove or cancel; the numerical error remains visible. A changed lifetime, CAD/anchor rejection or successful commit still clears the collection. Five targeted success/error/invalidation/cancellation checks passed. On the budget refusal no new CAD request, geometry or history was produced. Receipt: `evidence/simultaneous-surface-targets/precommit-refusal-retention.json`. No browser rerun or successful qualification of that GUI request is implied.
